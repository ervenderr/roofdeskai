<interfaces>
API (api/app/drafts.py, require_tenant = X-API-Key only; no api/ changes in this phase):
- `GET /drafts?kind=quote|review_reply[&status=...]` -> `[{id:int, kind, status, payload:object, input_hash, created_at:iso, decided_at:iso|null}]`, newest first, max 200, tenant-scoped in SQL.
- `POST /drafts/{id}/approve` (from pending) and `POST /drafts/{id}/reject` (from pending|needs_human) -> 200 row; 409 "draft not in a decidable state"; 404 "draft not found" (also for another tenant's id).
- statuses: pending, approved, rejected, needs_human, sent.

Payloads:
- quote: `contact_email?`, `customer_email?` (raw customer text, PII), `request: {service_id, qty, add_on_ids[], customer_type}`, and either `needs_human: {reason, missing[]}` (no quote) or `quote: {currency, total:str, lines:[{kind, ref, label, qty, unit_price:str|null, amount:str}]}` plus `email_text: str|null` and `check_failures?: str[]`. Note: status needs_human can also come with a quote and `email_text: null` + `check_failures` (the email failed checks), with no `needs_human` key.
- review_reply: `review_text`, `rating` (1-5), `platform` (google|tripadvisor|other), and `reply_text` (pending) or `violations: str[]` + `attempts: int` (needs_human).

Existing dashboard code:
- `data.ts`: `call(route, init, opts: { operator?: boolean })` redirects to /login with no session, `notFound()` for operator-only routes in tenant sessions, redirects to `/login?expired=1` on 401/403. `api<T>(route, opts)` throws on non-ok. `getSession()` returns null when not live.
- `session.ts`: `NavItem = { href, label, operatorOnly?, module? }`, `NAV`, `navFor(session, items)`; null session = operator with no modules.
- `session.check.mjs` imports `./session.ts` directly (Node 24 strips types); prints `session check ok`.
- `next.config.mjs` already swaps `review-actions` for `lib/review-actions.stub.ts` under EXPORT=1; no config change needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> server action | bound args (kind, id, action) are client-supplied |
| dashboard server -> API | tenant key from sealed cookie; API enforces tenant_id in SQL and RLS |
| API -> dashboard | draft payload contains customer PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | decideDraft bound args | mitigate | parseDecision whitelists kind/action and requires a positive safe integer id; anything else throws before any API call |
| T-12-02 | Elevation | another tenant's draft id | mitigate | API `_decide` filters `tenant_id=:t` and returns 404; dashboard maps 404 to "missing" message, never shows other data |
| T-12-03 | Elevation | operator session on tenant routes | mitigate | `call(..., { tenant: true })` and `requireTenantModule` call notFound() for non-tenant sessions |
| T-12-04 | Info disclosure | logs | mitigate | errors log only HTTP status and action; payloads never logged or put in URLs (redirect query uses fixed words) |
| T-12-05 | Tampering | double submit | mitigate | API 409 maps to "conflict" message; no crash, no second state change |
| T-12-06 | Spoofing/CSRF | server action POST | accept | Next server actions check Origin against Host; session cookie is SameSite=lax and httpOnly (phase 11) |
</threat_model>
