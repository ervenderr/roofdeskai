`dashboard/lib/session.ts` (only import: `node:crypto`; no enums, namespaces or parameter properties so Node type stripping works; use `export type` for types):
- `export type Session = { kind: "tenant" | "operator"; key: string; name: string; modules: string[]; exp: number }` (exp = unix seconds).
- `export const SESSION_COOKIE = "rd_session"` and `export const SESSION_MAX_AGE = 8 * 60 * 60` (seconds).
- private `keyFrom(secret)`: throw `Error("SESSION_SECRET must be at least 32 characters")` if missing or shorter than 32; return `createHash("sha256").update(secret).digest()` (32 bytes).
- `export function seal(s: Session, secret: string): string`: random 12-byte IV, `createCipheriv("aes-256-gcm", key, iv)`, encrypt `JSON.stringify(s)`, token = base64url of iv (12) + auth tag (16) + ciphertext.
- `export function unseal(token: string, secret: string): Session | null`: call keyFrom first (so a bad secret throws, not returns null), then in a try/catch decode, split, decipher with `setAuthTag`, JSON.parse; return null on any decrypt/parse failure (tampered or foreign cookie means no session; this is the boundary, not a swallowed error). After parse, validate shape: kind is "tenant" or "operator", key and name are non-empty strings, modules is an array of strings, exp is a number greater than `Date.now() / 1000`; otherwise null.
- `export type NavItem = { href: string; label: string; operatorOnly?: boolean; module?: string }` and `export const NAV: NavItem[]` = Overview "/", Conversations "/conversations", Prospects "/prospects" (operatorOnly), Outreach "/outreach" (operatorOnly), Calls "/calls" (operatorOnly), same order as today's layout.
- `export function navFor(session: Session | null, items: NavItem[] = NAV): NavItem[]`: null session (static demo) counts as operator with no modules; an item shows when (not operatorOnly or operator) and (no module or session.modules includes it). This is the AUTH-06 gating mechanism; phases 12-13 add module items.

Add `"check": "node lib/session.check.mjs"` to `dashboard/package.json` scripts. No new dependencies.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie -> Next server | `rd_session` value is attacker-controllable input |
| Next server -> FastAPI | dashboard forwards the session credential as X-API-Key or X-Admin-Key |
| login form -> checkKey | pasted key is untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing/Tampering | session.ts unseal | mitigate | AES-256-GCM auth tag rejects forged or edited cookies; shape and exp validated after decrypt; self-check covers tamper, wrong secret, expiry |
| T-11-02 | Information disclosure | cookie payload contains the API key | mitigate | payload encrypted (not just signed) so the key is unreadable client-side; httpOnly set in plan 02 |
| T-11-03 | Information disclosure | data.ts logging | mitigate | logs carry route and status only; key and SESSION_SECRET never logged or returned |
| T-11-04 | Elevation of privilege | tenant session calling operator routes | mitigate | `operator: true` gate calls notFound() before fetch; API require_admin is the backstop (403) |
| T-11-05 | Elevation of privilege | admin key exposure | mitigate | ADMIN_API_KEY removed from dashboard env; the admin key exists only inside an operator's sealed cookie |
| T-11-06 | Denial of service / weak secret | SESSION_SECRET | mitigate | keyFrom throws when missing or under 32 chars, so live mode fails loudly instead of sealing with a weak key |
| T-11-07 | Tampering | revoked key mid-session | mitigate | 401/403 from API redirects to /login?expired=1; session lifetime capped at 8h via exp |
</threat_model>
